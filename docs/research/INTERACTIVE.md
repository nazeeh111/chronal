It clears the paired crosshair when the source has no data. The [time-scale contract](https://github.com/tradingview/lightweight-charts/blob/c9ec1cec25583a0200f3c85ad9019d19c1d65f97/src/api/itime-scale-api.ts) distinguishes actual time ranges from logical indices, notes null/no-data states and bounded actual-time setting, and exposes fit/reset. Its [tutorial](https://github.com/tradingview/lightweight-charts/blob/c9ec1cec25583a0200f3c85ad9019d19c1d65f97/website/tutorials/how_to/set-crosshair-position.mdx) separately discusses mobile tracking without long-press. LICENSE/NOTICE inspected: Apache-2.0 with attribution notice, but no code is adopted here.

Transfer: make CHRONAL's existing session context directly selectable from chart click/tap, retaining slider/date/keyboard alternatives. Translate pointer coordinates using the SVG view box, not assuming browser CSS pixels equal chart units. Clamp to actual evaluated sessions and account explicitly for the initial-capital point. A unified session setter should update the cursor, date, account and command status; chart navigation must not mutate strategy selection or create fake market data. Only add linked panes if they answer a separate question. Do not import the chart library just for these controls.

**Quantopian pyfolio**, revision `4b901f6d73aa02ceb6d04b7d83502e5c6f2e81aa`: [timeseries.py](https://github.com/quantopian/pyfolio/blob/4b901f6d73aa02ceb6d04b7d83502e5c6f2e81aa/pyfolio/timeseries.py), lines870–901, obtains a drawdown's valley at minimum underwater value, last preceding zero as peak, first subsequent zero as recovery, and retains missing recovery. Lines931–1023 rank drawdowns and display peak/valley/recovery/depth/duration. This answers *where did the reported maximum drawdown happen and did it recover?* better than another scalar. Crucial countercheck: its duration uses generic business dates, unsuitable for CHRONAL's declared arbitrary synchronized sessions. Its cumulative path also does not explicitly prepend starting capital in these functions; copying this convention could miss CHRONAL's first-session loss.

Transfer: derive nonoverlapping contiguous underwater episodes from `[initial_cash, ...equity]`, rank by depth, show start/peak, trough, recovery or 'unrecovered', and observed underwater sessions. Peak may be the initial-capital anchor, which must be labeled as such rather than assigned a made-up prior date. Flat/all-cash paths have zero episodes, not a zero-depth fake episode. Recovered means reaching or exceeding the previous peak; drawdown depth uses the fixed episode peak. A trough action can select its exact chart/account session. This is an inspection of existing fixed results, not an additional backtest or selection criterion. Rank ties deterministically.

**Exposure countercheck**, pyfolio [pos.py](https://github.com/quantopian/pyfolio/blob/4b901f6d73aa02ceb6d04b7d83502e5c6f2e81aa/pyfolio/pos.py), lines32–48 and84–113, divides position *values* by portfolio values before concentration measures and excludes cash after normalization. CHRONAL currently exposes share inventory alongside aggregate invested/cash weights. Ranking raw share quantities as concentration would be false across assets with different prices. Per-asset weights require actual corresponding marked prices/values, carried through verification. Bounded useful alternative: per-session dollar changes and portfolio cash activity already supported by the ledger; do not advertise attribution without accounting for trades, prices and costs.

## Range analysis contract

A useful next control is an explicitly descriptive selected-session window, with net return, paired equal-weight return, excess percentage points, commissions and matching fills. It must display the selected start/end and number of returns. For inclusive sessions L..R, starting NAV is initial capital if L=0, otherwise equity[L-1]; ending NAV is equity[R]. Both candidate and baseline must use the identical session set. Cropping to equity[L] would silently drop the first selected return. Return excess is a difference of total returns, not the return of a self-financing long-short portfolio. No range should change the frozen winner, plan, exported canonical results, conditional bootstrap or complete-region metrics.

Distinguish a viewport-only range (whole-path metric context) from a rebased local diagnostic. A range-local drawdown resets its peak at the range's starting NAV, which can differ materially from the original full-path drawdown at that date. Label the convention if included; simpler first release should keep the existing full-path chart and add a plainly labeled local summary. Single-session windows are valid with one return. Reject reversed/absent dates without partially mutating state. Monthly cell selection could apply exactly its actual available sessions, but an empty month must remain nonselectable. Treat all range exploration as post hoc descriptive analysis; visually profitable windows do not establish alpha.

## Priority and tests

1. Direct chart session selection and previous/next controls with keyboard alternatives; test CSS scaling, initial anchor, final session, malformed dates, one-point paths and strategy switches.
2. Drawdown episode triage with exact trough navigation; hand controls: all-flat, first-day loss, equal-height peaks, full recovery, unrecovered tail, two separate episodes and deterministic equal depths.
3. Inclusive range inspection if time permits; hand-control every boundary, paired-session consistency, fees/fills at both endpoints, range reset, and frozen winner/canonical result immutability.
4. Export a filtered ledger only with an explicit filtered-export label and headers; retain canonical full-region CSV links separately. A share URL or persistence layer is unnecessary until report identity/source binding is designed.

Previous RD-Agent/skfolio evidence remains useful counterweight: candidate lineage and full trial registry matter; selection confidence cannot be manufactured by adding metrics or selecting a flattering subwindow. A richer terminal is useful when it links observed outcomes to their dates, cash and evidence. It does not establish trading profitability, live order state or out-of-sample validity beyond the registered experiment.
