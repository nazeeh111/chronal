# Investment agents and reinforcement learning: source inspection

Inspected 2026-10-21. This is a static public-source investigation, not an upstream runtime replication or investment-performance comparison. GitHub's native fetch connector resolved the revisions and returned the retained source bytes. Web browsing established the primary repository and paper context. No upstream package was installed or executed, no credentials were inspected, and no paid calls were made.

## Decision

Use a small deterministic portfolio and simulation core, with agents supplying evidence-bearing proposals through a narrow contract. Transfer current upstream mechanisms, not their complete dependency stacks. Build a coherent offline demonstration first. The strongest differentiation is a reproducible causal research record: what was knowable, what the agent actually saw, what it proposed, what the risk rules changed, and what was subsequently filled and scored.

The present versions of TradingAgents and ai-hedge-fund are substantially stronger on chronology and risk than their older, widely described versions. It would be inaccurate to position a new project as the first to offer next-session execution, deterministic risk caps, or filing-date filtering. The opportunity is to connect those mechanisms to immutable local data, actual cost-aware cash accounting, evaluation discipline, and an inexpensive agent interface.

## TradingAgents: explicit evidence roles, improved chronology, rating evaluation

Observed source:

- [`agents/managers/portfolio_manager.py`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/agents/managers/portfolio_manager.py) consumes the analyst and risk debate and tries typed `PortfolioDecision` output, falling back to a parsed text rating. The final output is a rating and investment thesis. The debate is an analysis mechanism, not deterministic order-level risk enforcement.
- [`dataflows/date_window.py`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/dataflows/date_window.py) and [`agents/tools.py`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/agents/tools.py) clamp dated tools against the graph's injected trade date rather than trusting a date chosen by the language model.
- [`dataflows/vendors/sec_edgar.py`, `_as_of`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/dataflows/vendors/sec_edgar.py#L156) filters facts on `filed <= as_of_date`, selects the latest eligible filing for a period, handles alternative taxonomy tags without summing duplicates, and distinguishes quarterly from year-to-date spans. This is more sound than merely filtering on fiscal period end.
- [`memory/log.py`, `get_past_context`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/memory/log.py#L104) includes only resolved outcomes with a recorded resolution date at or before the analysis date. [`memory/settlement.py`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/memory/settlement.py) enters at the first close strictly after the analysis date, requires the complete holding window, and aligns the benchmark to the stock's entry and exit dates.
- [`backtest.py`](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/backtest.py) explicitly evaluates independent rating cells. It does not carry positions, sizes, fills, or cash across dates. Its summary says text feeds are not archived and one model sampling per cell makes results indicative rather than repeatable. Alpha aggregates are parsed from rounded percentages, accurate only to 0.1 percentage point.

Transfer: typed analyst proposals, counterarguments grounded in source IDs, clamped access dates, and settled-outcome memory. Store raw retrieved evidence, prompt/model identity, output, and exact scoring values outside prose. Keep risk enforcement outside the model. Use multiple roles only when an ablation demonstrates a benefit over one analyst plus a critic.

Integration burden: the graph and tools use LangGraph/LangChain and vendor-specific data routing. Copying the complete workflow would add provider setup and many LLM calls. A narrow exported research packet plus validated decision import preserves subscription-based use and can work without separately billed APIs.

Time limits: a date cutoff is weaker than a verified timestamp cutoff; same-day filings and articles need a clear after-close convention or actual publication/acceptance time. A contemporary ticker-to-CIK map is not a full historic security master. Filing-vintage arithmetic does not establish that every fallback vendor or narrative input is point-in-time faithful. An LLM may already know outcomes from model training even when supplied tools are properly clamped.

## ai-hedge-fund: consequential recent refactor worth learning from

The observed commit is the 2026-10-19 v2.6.0 bump. Current source lives under `hedge_fund/`, not the historical persona-agent tree often described online.

- [`pipeline/session.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/pipeline/session.py) defines one advance operation: reconcile, execute the previously pending decision, mark the book, then assess. `SessionRecord` carries decisions, executions, positions, marks, cash, NAV, code version, mandate hash, and model identity. [`backtesting/fund.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/backtesting/fund.py) reuses this operation across actual benchmark sessions.
- [`portfolio/construction.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/portfolio/construction.py) distinguishes abstention from a neutral vote and separates long-only bearishness from permission to create a short position. Dollar-neutral construction goes flat when either side is missing. It explicitly notes that relative conviction is not a calibrated expected return.
- [`risk/limits.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/risk/limits.py) rejects nonfinite inputs, enforces position and gross-exposure limits, records clamp events, and leaves removed exposure in cash. Optional common-factor scaling preserves proportions. [`portfolio/validation.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/portfolio/validation.py) recomputes eligibility from analyst evidence and verifies contributions and final limits before submission.
- [`pipeline/clock.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/pipeline/clock.py) requires exact-session finite positive marks. Missing prices cause a failure instead of silently becoming a zero price or stale fill.
- [`data/client.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/data/client.py) is a Financial Datasets client. It requests metrics and insider trades using filing-date bounds; errors are separated from genuine absence. The server's compliance with its filtering contract was not independently verified here. `get_market_cap` prefers current company facts without an as-of parameter, so use requires tracing the caller before assuming historic fidelity.
- [`brokers/sim.py`](https://github.com/virattt/ai-hedge-fund/blob/4e1657ddc689e3939c481a8f0955444b10f02dc9/hedge_fund/brokers/sim.py) fills every order fully at its reference price. The file explicitly declares costs/slippage a future addition and margin unmodeled; negative cash is possible. This source is not a realistic execution benchmark.

Transfer: retain a proposal boundary, deterministic construction, exposure reductions that cannot increase another name, pre-execution reconciliation, and one replay/session accounting path. Add actual commission/slippage/cash/participation constraints in the simulator. The data and LLM protocols make an adapter feasible, but the default factory still requests provider credentials and FDClient uses an external vendor. Do not inherit those defaults under the user's free-local constraint.

## FinRL: useful research interface, unsafe to inherit assumptions unchanged

Strength: a clear Gymnasium environment represents observation, action, portfolio transition, reward, and train/test behavior; it provides an established seam for learned policies. [`env_stocktrading_np.py`](https://github.com/AI4Finance-Foundation/FinRL/blob/c0018c25de864157dc8470f0047b0d10ec721715/finrl/meta/env_stock_trading/env_stocktrading_np.py) includes buy/sell fees, turbulence-triggered liquidation, a next-row transition, and vectorized state arrays.

Observed limitations in the selected source:

- [`preprocessors.py` lines 171-180](https://github.com/AI4Finance-Foundation/FinRL/blob/c0018c25de864157dc8470f0047b0d10ec721715/finrl/meta/preprocessor/preprocessors.py#L171) uses forward fill followed by backward fill. Backward filling a leading missing feature imports a later observation. With the default branch the fill is across the row frame rather than grouped by ticker; with incomplete tickers enabled it is grouped but backward filling remains.
- [`clean_data`, lines 194-199](https://github.com/AI4Finance-Foundation/FinRL/blob/c0018c25de864157dc8470f0047b0d10ec721715/finrl/meta/preprocessor/preprocessors.py#L194) by default drops ticker columns containing any missing close over the input span. If used over a full historical interval, this chooses the universe partly using future availability. This is a conditional source-level risk, not a measured estimate of performance inflation.
- `reset(seed=...)` accepts a seed but uses global NumPy random calls and does not pass the seed to Gymnasium or construct a seeded generator. The selected environment therefore does not itself guarantee reproducibility through the advertised reset argument.
- Buy affordability is `amount // price`, but the actual debit includes the buy fee. Independent arithmetic: 100 cash, 100 price, a 0.1% fee, and one requested share produces -0.1 cash. The quantity calculation should divide by all-in cost, not price alone.
- The environment uses next-row turbulence to decide whether to override a previously selected action and liquidate at the next-row price. That is a simulation convention requiring an explicit execution/observation interpretation, not proof of tradable risk control.

Transfer: keep RL an optional adapter after the simulator's accounting and causality tests pass. Make observations read-only views of data available at the decision timestamp; use seeded generators, cash-safe affordability, and warmup exclusion rather than backward filling. Do not make heavy RL and optimization dependencies part of the default installation merely to check a feature box. No policy was trained and no FinRL performance claim was replicated.

## InvestorBench: useful memory experiment, not a ready execution core

The [ACL 2025 primary paper](https://aclanthology.org/2025.acl-long.126/) provides the research context; the repository code above is the basis for these findings. Its useful distinction is evaluating financial decision agents across task/asset settings with layered memory, rather than adding more investor personas.

- [`src/memory_db.py`](https://github.com/felis33/INVESTOR-BENCH/blob/87e0f7bc83baf7d89fbdc1a51f92458f8d4ee11a/src/memory_db.py) combines semantic similarity, normalized importance, and exponential recency; evidence access receives outcome feedback; memories decay and move between short/mid/long layers. The retrieval implementation filters by symbol and layer, not an as-of timestamp. Causality relies on sequential ingestion and checkpoint discipline.
- [`src/agent.py`](https://github.com/felis33/INVESTOR-BENCH/blob/87e0f7bc83baf7d89fbdc1a51f92458f8d4ee11a/src/agent.py) records cited memory IDs with actions, a useful basis for attribution ablations. [`src/embedding.py`](https://github.com/felis33/INVESTOR-BENCH/blob/87e0f7bc83baf7d89fbdc1a51f92458f8d4ee11a/src/embedding.py) requires an OpenAI embedding key, while memory uses Qdrant. Local model support for generation does not make this inspected embedding path free and local.
- [`market_env.py`](https://github.com/felis33/INVESTOR-BENCH/blob/87e0f7bc83baf7d89fbdc1a51f92458f8d4ee11a/src/market_env.py) carries next-day price differences in the environment observation object. The inspected [`chat/prompt/vllm_prompt.py`](https://github.com/felis33/INVESTOR-BENCH/blob/87e0f7bc83baf7d89fbdc1a51f92458f8d4ee11a/src/chat/prompt/vllm_prompt.py) gates their prompt insertion to WARMUP; it would be inaccurate to call this proof that every TEST prompt leaks future prices. However, putting labels and observable inputs in one object is an unnecessarily fragile boundary.
- A precise inconsistency: environment `cur_future_price_diff = (price - future_price) / price`; warmup action selection chooses BUY when that value is positive. A rise 100 to 110 yields -0.1 and therefore SELL. The prompt describes the quantity as next-day minus current-day. This sign mismatch is directly observable in source; it was not executed upstream.
- [`eval_pipeline.py`](https://github.com/felis33/INVESTOR-BENCH/blob/87e0f7bc83baf7d89fbdc1a51f92458f8d4ee11a/src/eval_pipeline.py) computes action-weighted log returns, sums them as cumulative reward, then passes those log returns to a drawdown routine that compounds `1+r`. These quantities need explicit labels and consistent conversion. Independent arithmetic for one long loss from 100 to 50: the true drawdown is 50%, whereas treating log(0.5) as a simple return gives approximately 69.31%. Do not reuse this metric path unchanged.

Transfer: store evidence and cited IDs, run retrieval-with/without-memory experiments, and defer outcome feedback until its resolution timestamp. Start with standard-library full-text/BM25-like retrieval or an existing local embedding runtime, not a mandatory vector service or paid embedding endpoint. Avoid automatic importance reinforcement until a training-only experiment shows it improves held-out results; outcome reinforcement can encode selection bias and stale regimes.

## Concrete local platform contracts

1. **Dataset:** immutable file hash, provider/source, timezone, event time, available-at time, retrieval time, adjustment convention, missing-data and universe policy. Synthetic demo data must be conspicuously labeled. Importing a CSV does not establish point-in-time correctness.
2. **Research packet:** decision cutoff, trailing-only features, allowed evidence IDs and timestamps, portfolio state, benchmark, and risk mandate. Keep outcome labels in an evaluator-owned structure unavailable to strategy code.
3. **Proposal:** desired weights or bounded scores, cited evidence IDs, rationale, model identity, and abstention. Validate the complete object and all numeric values. Confidence is not a calibrated probability or expected return.
4. **Risk and fills:** deterministic position/gross/turnover limits, next-session execution, cash-safe affordability including fees, explicit slippage/volume policy, and logged rejection/partial-fill reasons. Start long-only and unlevered; adding shorting without borrow and margin modeling makes fidelity worse.
5. **Evaluation:** real cash/NAV ledger and independently verified simple-return metrics; paired baseline comparisons with identical fees/calendar/universe; held-out periods; parameter-selection separation; complete trial registry; outcome-timestamp-aware memory; failure counts and coverage beside scores.
6. **Replay:** retain dataset, config, code, proposal, prompt/output where applicable, risk changes, fills, ledger, and hashes. Replaying a stored LLM output is reproducible accounting, not reproducible model generation or evidence of predictive ability.

This combination is a defensible engineering direction, not an established claim that a new repository outperforms these projects. The earliest useful result is a fully reproducible local research run with an explainable decision trail and tests that make lookahead and accounting errors fail visibly.
