## Useful patterns from pinned code

1. **Gloomberb**, `gloom-sh/gloomberb@d24837977d1ab95047e9ea11e79f7463fe330c6a`. Inspected license, keyboard handlers, list model, list model tests and root shortcut tests. License is MIT with the usual copyright/permission preservation requirement and an additional nonbinding attribution request. Keyboard handling separates movement from activation; Home/End remain ordinary caret actions unless modified. Tests specifically cover keeping variable-height selected results visible in short viewports, paging by rendered lines, ticker-context inference only for required arguments, preserving text-search queries and alias equivalence. Transfer: describe and expose actual supported CHRONAL commands, accept a suggestion without executing it, keep the selected option visible, and make any selected asset context explicit. Do not graft its plugin routing, broker actions or data feeds into a standalone report.

2. **Longbridge Terminal**, `longbridge/longbridge-terminal@9120d0fddd1c47b3087b280b0f2742ec413847a9`. Inspected Apache-2.0 license, CLI completion, TUI input routing and search widget. The search widget keeps up to 20 selected results in memory, removes duplicates before moving a selection to the front, shows history only for an empty query, uses Escape to close, and separates direct typed query Enter from a selected dropdown result. The CLI completion module delegates to a command specification. These are inspected implementation behaviors, not replicated test outcomes. Transfer: bounded tab-local command history, restoring the draft after moving down beyond newest history, and deterministic completion from known local strategies/sections/assets. Avoid copying its network-backed discovery and trading capability into the offline artifact.

3. **Bloomberg-inspired self-hosted terminal**, `triphopp/bloomberg-terminal@8f7b9bb9867d6be5e07659fbe8a637e159d4e3b8`. Inspected README, terminal autocomplete/registry/validator and architecture document. The full pinned tree contains no file with `license` in its path, so no permission to copy its implementation is inferred. Autocomplete offers command-prefix results with descriptions and parameter hints; execution detection uses an exact registered first-word match to avoid letting a short command prefix hijack symbol search. Validation checks required and maximum argument counts. Transfer ideas only: a small allowlisted vocabulary, clear usage errors, exact-name asset resolution, and completion that never expands arbitrary input to an action. No finance or AI claims in the README were validated. No terminal-specific test file was present beside the inspected terminal implementation; this is not a claim that the entire project lacks tests.

## Recommended bounded implementation

**A. Command discovery and replay.** The present report only has a command input and help modal. Add visible described suggestions derived from the actual command vocabulary and available strategy/asset names, plus a bounded in-memory submitted-command history. Completion only changes the input; Enter remains the explicit action. Scope ArrowUp/Down handling to the command field. Preserve a draft across history navigation. Do not capture Home/End, modified shortcuts, or Tab when no completion applies. Clear history is useful and should affect only tab memory, not model results or canonical exports. Regression cases: empty/malformed input, no-match input, duplicate history, oldest/newest bounds, draft restoration, quoted/spaced asset names, strategy names resembling commands, and immutable frozen winner.

**B. Synchronized asset drilldown.** The present asset selector only filters fills; intent rows and holdings stay disconnected. Use one exact selected-asset context shared by holdings, simulator-authored intent rows and fills, with a native selector available independently of commands. A descriptive asset command may set that selector and navigate to account/execution. Keep a visible All-assets state distinct from a literal asset named `all`; do not infer asset weights from quantities or change portfolio-level metrics when selecting an asset. For arbitrary valid asset names, prefer a 1-based `asset #N` command and exact-name lookup instead of introducing a quoting language. Regression cases: literal `all`, names with spaces/punctuation, asset with no fills at selected session, existing side/session filter combinations and changing strategy without changing data context.

These additions earn their cost by reducing retyping and linking real recorded evidence. A simulated market ticker, chat assistant, opaque scoring badge or copied Bloomberg branding would add little evidence or capability. CHRONAL remains a reproducible offline research artifact, not an institutional market-data terminal.

## Delivered decisions

CHRONAL implements a searchable command palette with descriptions and native buttons. Choosing a command only fills the command bar; Enter runs the existing allowlisted interpreter. History keeps at most 100 submitted commands in report memory, removes consecutive duplicates and restores an unfinished draft. Alt+Up/Down is scoped to the command input; normal editing keys remain available. Native datalist completion was tried but did not visibly open in the tested embedded browser, so the explicit modal palette is the supported route.

The complementary addition is a full-region execution finder. Asset, outcome and exact recorded reason filters intersect; paginated native buttons jump from an actual request to its linked session/account/model/execution evidence. This directly exposes requests without relying on fills or risk events. Finder and fill-ledger filters have explicit separate scopes. A global asset filter was not added because its implications for portfolio totals and different table scopes require a separate design decision. No copied branding, feeds, broker actions or AI claims were imported.
