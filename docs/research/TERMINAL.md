## Concrete findings and decisions

1. **Fincept Terminal: command-driven work rather than a fake market display.** `CommandParser.cpp` lines38–122 routes help, registered single-token actions, symbol context and longest-prefix verb/object commands; unknown input has an explicit error. `CommandPalette.cpp` lines48–70 advertises Escape/Enter interaction. Recommendation: an allowlisted CHRONAL command field supporting existing report views and strategy selection, visible help, explicit unsupported commands, keyboard focus and Escape behavior. Do not run arbitrary shell text or imply orders can be sent. A dense terminal palette alone is cosmetic; context and useful actions make it functional. License AGPL-3.0-or-later: transfer ideas only, no source or artwork copying.

2. **OpenBB backend examples: explicit panel contracts and typed controls.** The inspected grouping widgets JSON defines endpoint, category, grid dimensions and named typed parameters with fixed options or an options endpoint. `main.py` serves these contracts separately from data-fetch endpoints, and returns explicit non-200 errors. Recommendation: preserve one selected-strategy context across chart/risk/fill panels, expose the dataset/run identity permanently, export the actual selected record, and keep report controls connected to real data. Building an OpenBB plugin, provider authentication or server deployment adds no necessary benefit to this offline research bundle. This sample is MIT; no sample code copied. Its permissive CORS and unauthenticated sample API are not a security design to adopt.

3. **Microsoft RD-Agent: experiment lineage and rejected hypotheses matter.** `factor_runner.py` lines66–84 recursively evaluates the baseline and propagates explicit train/validation/test dates. Lines46–63 deduplicate new factors via cross-sectional correlation averaged by datetime; lines101–112 reject empty outputs or redundant factors; lines164–193 execute concrete experiment configurations. `model_runner.py` similarly injects candidate code and hyperparameters into experiment workspaces. Recommendation: make rejected/invalid candidates and frozen trial budget visible and retain baseline/parent identifiers. Do not port the factor deduplication formula blindly: near-negative correlation, date availability and sample dependence require different handling. Full autonomous generated Python plus Docker/model-service loop is a substantial separate product, not a feature justified by an agent graph or a profitable-looking example. MIT; no copied code. No RD-Agent return/alpha claims were verified.

4. **Hummingbot: candle simulation and live order state are distinct capabilities.** `backtesting_engine_base.py` lines225–241 exposes an explicit trade-cost parameter; lines269–291 advance simulated execution, and lines321–336 retain a full executor ledger separately from the controller's bounded historical view. `client_order_tracker.py` lines45–117 tracks active, cached and lost orders, including orders still eligible for late fills. Recommendation: report costs and ledger events visibly; never label CHRONAL's expiring daily target fills as live order management. A genuine exchange adapter requires acknowledgement, partial fills, late fills, cancellation and lost-order reconciliation, beyond a buy/sell UI. Apache-2.0; no source copied. No order-book fidelity or live exchange performance established by these files.

5. **skfolio: selection uncertainty needs all trials and assumptions.** `_measures.py` lines1383–1474 defines DSR from every evaluated trial's same-frequency, per-period Sharpe, while expressly assuming independent normally distributed trial Sharpes and warning about correlated grids. `_walk_forward.py` lines117–145 explains execution-delay-aware purging. Recommendation: preserve CHRONAL's existing delayed-fill purge and registered candidate set, label conditional bootstrap intervals as conditional, and expose the number of evaluated trials. Do not add a DSR confidence badge from just the selected candidate or treat a small set of correlated candidates as independent evidence of alpha. BSD-3-Clause; no implementation copied. A future DSR implementation requires explicit convention, dependence caveat, all-trial input and hand-calculated controls.

6. **grokbot-field-notes: workflow notes, not trading research.** `AGENTS.md` lines60–61 ties bug fixes to reproduction and refactors to behavioral checks. `ANTIPATTERNS.md` lines172–190 discusses testing the exact demonstrated path and effects on removed behavior. Transfer: run the installed package's exact demo and full replay commands, inspect current mobile rendering and retain adverse findings. These files were read as untrusted source material, not adopted as instructions. Their broad agent roster and claimed workshop provenance were not verified; they provide no financial performance evidence. No content copied.

## Priorities for this iteration

Implement terminal navigation with actual allowlisted commands, coordinated strategy context, persistent offline/synthetic/source identity, accessible density and explicit unavailable metrics. Have an independent specialist probe accounting/availability boundaries and preserve the existing honest holdout results. Useful further financial expansion is a separately registered real-data experiment with adjustment/delisting/data-rights provenance; real trading, paid data, credentials and deployment remain outside authorization. No amount of terminal styling or added metric names proves hedge-fund quality or profitable alpha.
